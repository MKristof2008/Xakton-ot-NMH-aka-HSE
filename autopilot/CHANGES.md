## 1. Зачем это

Проект проверяет сообщение, когда его вставили вручную. Автопилот добавляет
второй контур: **сам собирает поток сообщений из сети, сам их проверяет и
сам дообучает модель** на том, что подтвердилось.

Четыре компонента, как в задаче:

| Компонент | Файл | Что делает |
|---|---|---|
| Collector | `collector.py`, `feeds.py`, `robots.py`, `textnorm.py` | тянет RSS, Telegram, HTML-ленты, JSON API; чистит текст, убирает дубли |
| Analyzer | `model.py`, `corpus.py` | локальная модель даёт P(фейк); индекс корпуса ищет похожие материалы |
| Verifier | `verifier.py` | ставит метку `fake` / `real` / `uncertain` с обоснованием |
| Trainer | `trainer.py`, `training_data.py` | дообучает модель и решает, публиковать ли новую версию |
| Orchestrator | `orchestrator.py`, `cli.py`, `statusline.py` | крутит цикл 24/7, ведёт логи и сводку |

## 2. Как принимается решение «фейк / не фейк»

Порядок проверки одного материала (`verifier.verify`):

1. **Локальная модель** считает P(фейк). Это только сигнал: сама по себе
   вероятность метку не ставит.
2. **Опровержение фактчекеров.** Если материал совпал с карточкой из
   источника с ролью `factcheck` — метка `fake`, уверенность 0.9.
3. **Проверка утверждений пайплайном проекта.** Модель извлекает до трёх
   фактов и сверяет их с материалами (`extract_claims` → `evaluate_claims`
   → `validate_result`). Валидатор проекта детерминированно отбрасывает
   цитаты, которых нет в источнике.
4. **LLM-арбитр** для спорных случаев. Обязан вернуть дословные цитаты;
   цитаты проверяются кодом. Нет цитаты — нет метки.

Нет основания — метка `uncertain`, материал возвращается в очередь.

**Почему это важно:** модель не может подтвердить сама себя. Если бы
прогноз модели шёл в обучение, ошибки закреплялись бы с каждым циклом.

## 3. Три проблемы из первого прогона и что сделано

### 3.1. F1 = 1.0 блокировал обновления

**Причина:** отложенная выборка собиралась из того же файла, на котором
обучена модель проекта. Её F1 на этой выборке всегда идеален — это утечка.
Правило «F1 должен вырасти» при 1.0 невыполнимо.

**Что сделано:**

- обучающий корпус собирается из данных проекта (`training_data.py`),
  а не из посторонних файлов;
- holdout пополняется свежими подтверждёнными метками: стратификация по
  классам, дедуп по нормализованному тексту, потолок `holdout_max_per_class`;
- правило активации (`trainer._decide`) теперь двухрежимное:
  - **первая активация** — по абсолютному порогу `min_accept_f1` /
    `min_accept_precision`, потому что сравнивать не с чем;
  - **дальше** — рост F1, **либо** равный F1 при улучшении LogLoss или
    ROC-AUC, **либо** равный F1 при росте выборки. Precision не должен
    упасть больше `max_precision_drop`.

**Результат на реальных данных:** F1 0.88, precision 0.79, recall 1.0,
ROC-AUC 0.99 — вместо искусственной единицы.

### 3.2. Очередь `uncertain` могла крутиться вечно

**Что сделано:**

- счётчик попыток: не больше `max_verify_attempts` (3) на материал;
- TTL: через `uncertain_ttl_hours` (48 ч) материал уходит в
  `archived_uncertain`;
- бюджет модели проверяется **до** обработки материала: если вызовов не
  хватает, попытка не тратится;
- архивные материалы не попадают в обучение, но остаются для отчётности
  и экспорта.

### 3.3. Пороги были завышены и зашиты в код

**Что сделано:** все пороги вынесены в `autopilot/config.json` с
пояснениями и продублированы в README:

| Параметр | Значение | Смысл |
|---|---|---|
| `min_label_confidence` | 0.60 | ниже — метка не идёт в обучение |
| `claims_full_support_conf` | 0.80 | все утверждения подтверждены |
| `claims_full_contradict_conf` | 0.85 | все утверждения опровергнуты |
| `claims_partial_conf` | 0.70 | часть утверждений подтверждена |
| `claims_partial_share` | 0.50 | доля опровергнутых для метки `fake` |
| `claims_max_unresolved_share` | 0.50 | больше — «подтверждено» не считается |
| `min_sources_for_real` | 2 | независимых домена для метки `real` |
| `max_verify_attempts` | 3 | попыток проверки материала |
| `uncertain_ttl_hours` | 48 | после — в архив |

Дополнительно ужесточена логика вердикта: `real` больше не ставится, если
половина утверждений осталась без ответа; `fake` не ставится, если
опровергнуто меньше половины утверждений.

## 5. Команды

```powershell
cd <корень репозитория>

.\autopilot\RUN_AUTOPILOT.ps1              # цикл 24/7 (ставит зависимости)
.\autopilot\RUN_AUTOPILOT.ps1 -Once        # один цикл
.\autopilot\RUN_AUTOPILOT.ps1 -NoLlm       # без вызовов модели
.\autopilot\RUN_AUTOPILOT.ps1 -Status      # только сводка

.\autopilot\STATUS.ps1                     # красивая сводка
.\autopilot\STATUS.ps1 -History 5          # + история обучения
.\autopilot\STATUS.ps1 -Json               # машинный формат

.\autopilot\STOP_AUTOPILOT.ps1             # остановить
```

То же через Python:

```powershell
py -3 -m autopilot run --once
py -3 -m autopilot collect
py -3 -m autopilot verify --limit 20
py -3 -m autopilot train --no-en
py -3 -m autopilot status --holdout --history 5
py -3 -m autopilot items --label fake
py -3 -m autopilot models
py -3 -m autopilot models --promote <version>     # откат версии
py -3 -m autopilot export --out autopilot/data/labeled.csv
```

## 8. Что нужно сделать вручную

1. **Ключ модели.** В `ml/.env` вписать `LLM_API_KEY`, `LLM_BASE_URL`,
   `LLM_MODEL` (шаблон — `.env.example`). Без ключа работают только
   детерминированные проверки: совпадения с опровержениями фактчекеров,
   поэтому меток будет мало.
2. **Первый цикл.** `.\autopilot\RUN_AUTOPILOT.ps1 -Once`, затем
   `.\autopilot\STATUS.ps1` — посмотреть, сколько материалов размечено.
3. **Влить ветку.** `feat/autopilot` запушена, изменения в `main` не
   вносились.

## 9. Ограничения, о которых стоит знать

- **Данных для обучения мало.** Честный корпус проекта — порядка 180
  примеров, holdout — 37. Метрики на такой выборке шумные; при накоплении
  подтверждённых меток автопилота качество оценок вырастет.
- **Собранный корпус как источник меток слабый.** Карточки фактчекеров и
  сообщения агентств дают стилевые метки с низким весом (`0.5`). Это
  дополнение к курируемым данным, а не замена.
- **CPU-only.** TF-IDF + LogReg учится секунды. Ветка BERT включается
  автоматически при наличии CUDA и `torch`+`transformers`.
- **Внешние источники нестабильны.** Часть площадок отдаёт 403 для простых
  HTTP-клиентов — для них поднимается Playwright. Если источник продолжает
  падать, он уходит на паузу (`failure_cooldown_s`).
- **Модель не публикуется в приложение по умолчанию.** `promote_to_app:
  false`, чтобы не менять артефакты приложения без решения команды.
