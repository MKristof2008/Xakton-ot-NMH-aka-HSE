# Автопилот BAYKAM

Автономная система, которая в фоне собирает контент из сети, проверяет его на
«фейк / не фейк» и на проверенных данных дообучает собственную модель.
Работает поверх существующего пайплайна «До репоста» (`ml/doreposta`) и не
меняет ни один файл приложения: весь код — в этом каталоге.

```
источники ──► Collector ──► SQLite ──► Analyzer ──► Verifier ──► метки
 (RSS, Telegram, HTML, API)              (локальная   (база знаний,  fake / real /
                                          модель)      цитаты, LLM)  uncertain
                                                             │
                                                             ▼
                                                    Trainer ──► модель ──► Analyzer
```

## Что делает каждый компонент

| Компонент | Файл | Задача |
|---|---|---|
| **Collector** | `collector.py`, `feeds.py`, `robots.py`, `textnorm.py` | обход RSS/Atom, Telegram-веб (`t.me/s/…`), HTML-лент по CSS-селекторам и JSON API; Playwright для JS-страниц; очистка текста; дедупликация (SHA-256 + SimHash); rate-limit, ретраи, `robots.txt`, предохранитель от «битых» источников |
| **Analyzer** | `model.py`, `corpus.py` | локальная модель даёт P(фейк); индекс собранного корпуса ищет похожие материалы |
| **Verifier** | `verifier.py` | метка только при внешнем основании: карточка фактчекеров → проверка утверждений пайплайном проекта (`extract_claims` → `evaluate_claims` → `validate_result`) → LLM-арбитр с обязательными дословными цитатами; нет основания — `uncertain` |
| **Trainer** | `trainer.py` | дообучение TF-IDF + LogReg (CPU) или русского BERT (GPU); holdout, сравнение F1/precision со старой версией, промоушен только при росте |
| **Orchestrator** | `orchestrator.py`, `cli.py` | цикл «сбор → скоринг → проверка → дообучение», логи в консоль и файл, Ctrl+C завершает после шага |

## Запуск (Windows PowerShell)

```powershell
cd "C:\Users\mvinn\Desktop\Xakton ot BAUMS\repo"

# первый запуск: поставит зависимости и браузер Playwright, затем пойдёт цикл
.\autopilot\RUN_AUTOPILOT.ps1

# один цикл без бесконечного ожидания (проверка)
.\autopilot\RUN_AUTOPILOT.ps1 -Once

# без вызовов модели (только локальный классификатор и база знаний)
.\autopilot\RUN_AUTOPILOT.ps1 -NoLlm

# сводка состояния: посты, метки, модель, источники
.\autopilot\STATUS.ps1
.\autopilot\STATUS.ps1 -History 5

# остановить
.\autopilot\STOP_AUTOPILOT.ps1
```

Ключ модели берётся из `ml/.env` (`LLM_API_KEY`, `LLM_BASE_URL`, `LLM_MODEL`).
Без ключа автопилот работает: локальная модель и база знаний продолжают
отвечать, а материалы без основания возвращаются в очередь — их проверит
следующий запуск уже с ключом.

### Отдельные шаги

```powershell
py -3 -m autopilot collect                 # один проход по источникам
py -3 -m autopilot verify --limit 20       # проверить 20 материалов
py -3 -m autopilot train --no-en           # обучить и сравнить с текущей моделью
py -3 -m autopilot train                   # то же, но с английским корпусом
py -3 -m autopilot status                  # наглядная сводка в консоли
py -3 -m autopilot status --history 5      # + история дообучения
py -3 -m autopilot status --holdout        # состав и насыщение отложенной выборки
py -3 -m autopilot status --json           # машинный формат
py -3 -m autopilot items --label fake      # последние размеченные материалы
py -3 -m autopilot sources                 # состояние источников
py -3 -m autopilot models                  # версии модели
py -3 -m autopilot models --promote v20261122_013000   # откат/переключение
py -3 -m autopilot export --out autopilot/data/labeled.csv
```

Все команды запускаются из каталога `repo/`.

## Стартовый набор источников

В `config.json` уже настроен сбалансированный набор — 14 источников трёх ролей:

| Роль | Источники | Зачем |
|---|---|---|
| `news` (доверенные СМИ) | ТАСС, РИА, Интерфакс, Lenta, Коммерсантъ, Ведомости, ЦБ РФ | эталон фактов, из них строится подтверждение |
| `factcheck` (опровержения) | Проверено.Медиа, StopFake, EU vs Disinfo, Snopes | сильнейшее основание для метки `fake` |
| `news` (Telegram, низкий вес) | Breaking Mash, Baza, Readovka | источник спорных постов, которые и надо проверять |

Telegram-каналы помечены `reliability: 0.35–0.45`: это не «источники истины»,
а поток для проверки. Именно их материалы чаще всего получают `uncertain`
и уходят в арбитраж.

`euvsdisinfo` выключен (`enabled: false`): его `robots.txt` запрещает обход
ленты. Включайте, если политика сайта изменится.

## Как добавить новый канал или сайт

Откройте `autopilot/config.json` и добавьте элемент в `sources`.

**RSS/Atom** (проще всего):

```json
{"id": "nakanune", "name": "Накануне.RU", "kind": "rss",
 "url": "https://www.nakanune.ru/rss/news.xml",
 "role": "news", "reliability": 0.7, "lang": "ru", "rate_limit_s": 1.5}
```

**Telegram-канал** (без токена бота, читается публичная веб-версия):

```json
{"id": "tg_sirena", "name": "Telegram: Sirena", "kind": "telegram",
 "url": "https://t.me/s/sirenanews", "role": "news",
 "reliability": 0.4, "lang": "ru", "rate_limit_s": 2}
```

**Фактчекинг** (карточки опровержений — сильнейшее основание для метки `fake`):

```json
{"id": "snopes", "name": "Snopes", "kind": "rss",
 "url": "https://www.snopes.com/feed/", "role": "factcheck",
 "reliability": 0.9, "rate_limit_s": 2}
```

**HTML-лента с CSS-селекторами**:

```json
{"id": "custom", "name": "Сайт", "kind": "html",
 "url": "https://example.ru/news", "role": "news",
 "item_selector": "div.news-item", "title_selector": "h3",
 "link_selector": "a", "date_selector": "time", "requires_js": false}
```

**JSON API**:

```json
{"id": "custom_api", "name": "Сервис", "kind": "api",
 "url": "https://api.example.ru/v1/news", "role": "news",
 "items_path": "data.items",
 "field_map": {"title": "headline", "text": "summary",
               "url": "link", "published_at": "publishedAt"}}
```

Поля источника:

- `kind` — `rss` | `telegram` | `html` | `api`;
- `role` — `news` (обычные издания) или `factcheck` (опрос достоверности);
- `reliability` — 0–1, вес источника при принятии решения;
- `rate_limit_s` — минимум секунд между запросами к домену;
- `requires_js` — поднимать Playwright для страницы;
- `enabled: false` — выключить, не удаляя;
- `headers` — дополнительные заголовки.

После правки конфига перезапускать ничего не нужно: следующий цикл читает
`config.json` заново (`Ctrl+C` и повторный запуск для смены интервала).

## Как принимаются решения

Метка `fake` / `real` ставится только при проверяемом основании:

1. **Опровержение фактчекеров** — материал совпал с карточкой из источника
   с ролью `factcheck` (совпадение по значимым словам ≥ 0.2).
2. **Проверка утверждений пайплайном проекта** — модель извлекает факты из
   материала и сверяет их с текстами доверенных источников; каждая цитата
   проверяется детерминированно (`validate_result`); выдуманная цитата
   отбрасывается, статус понижается.
3. **LLM-арбитр** для спорных случаев: обязан вернуть дословные цитаты,
   иначе метки нет.

Собственный прогноз модели (`fake_prob`) **никогда** не становится меткой —
он только сигнал и приоритет для Active Learning. Если оснований нет,
материал получает `uncertain` и возвращается в очередь: следующий цикл
проверит его снова (до трёх попыток, затем `uncertain` окончательно).
Так материал не «сгорает», если модель временно недоступна.

## Проверка на живых данных

```powershell
py -3 autopilot/smoke_live.py            # сквозная проверка на живых данных
py -3 autopilot/smoke_live.py --skip-llm # без вызовов модели
```

Сквозной сценарий: модель загружена → предсказание вероятности → правило
опровержения на живых карточках фактчекеров → проверка ложного и верного
утверждения пайплайном проекта → отбрасывание выдуманных цитат → обучение
с фиксацией решения в журнале. Рабочая база только читается, всё остальное —
на временном каталоге.

## Обучение и защита от деградации

Бэкенд выбирается под железо: `TF-IDF + LogReg` на CPU, BERT на GPU
(`trainer.backend = "auto"`).

**Отложенная выборка** (`autopilot/data/models/holdout.jsonl`):
- строится стратифицированно по классам, без дублей (отпечаток текста
  не зависит от регистра и пунктуации);
- пополняется свежими подтверждёнными метками автопилота — не более
  `eval_share_verified` доли от новых и до `holdout_max_per_class` на класс;
- в обучение не попадает никогда.

**Метрики:** F1, precision, recall, accuracy, LogLoss, ROC-AUC. Считаются
на русских примерах — английский корпус иначе завышает F1 и скрывает
деградацию на русском.

**Откуда берутся обучающие данные.** Только из самого проекта
(`autopilot/training_data.py`), по убыванию веса:

| Источник | Файл / таблица | Метка |
|---|---|---|
| обратная связь пользователей | `backend/...` таблица `feedback`, поле `expected` | как ждали пользователи |
| эталонный набор | `ml/data/eval_set.json` | `правда` → real, `фейк` → fake |
| курируемая база фактов | `ml/lakmus/data/kb_facts.json` | `true` → real, `false_claim` → fake |
| собранный корпус | `autopilot/data/autopilot.db` | фактчек → fake, агентство → real (низкий вес) |

Кейсы с ответом «непонятно» и факты со статусом `mixed` в обучение не идут:
неоднозначная метка портит модель сильнее, чем её отсутствие.

**Почему F1 бывает ровно 1.0.** Если обучающий корпус и отложенная выборка
собраны из одного и того же набора, метрики старой модели на этой выборке
идеальны — это утечка, а не качество. Проверить текущее состояние:

```powershell
py -3 -m autopilot status --holdout
```

Пока выборка «насыщена» (F1 = 1.0), различать версии по F1 бессмысленно —
система автоматически переходит на LogLoss / ROC-AUC / объём данных.
Реальным сигналом станет пополнение выборки подтверждёнными метками
автопилота (`origin=verified`): они не входили в обучение ни одной версии.

**Правило активации** (`trainer._decide`). Два режима:

1. Если активная модель — проектный бейзлайн, обученный на том же корпусе,
   что и holdout, сравнение с ним недостоверно (утечка: F1 всегда 1.0).
   Тогда действует абсолютный порог `min_accept_f1` / `min_accept_precision`.
   Это позволяет автопилоту выпустить первую собственную версию.
2. Дальше сравнение честное: нужен рост F1, **либо** равный F1 при улучшении
   LogLoss или ROC-AUC, **либо** равный F1 при росте обучающей выборки.
   Precision не должен упасть больше `max_precision_drop`.

| Параметр | Значение | Смысл |
|---|---|---|
| `min_f1_gain` | 0.005 | строгий рост F1 |
| `f1_tolerance` | 0.005 | какой F1 считать «равным» |
| `min_logloss_gain` | 0.002 | улучшение вероятностей при равном F1 |
| `min_auc_gain` | 0.002 | улучшение ранжирования при равном F1 |
| `min_data_growth` | 0.10 | рост объёма данных при равном F1 |
| `max_precision_drop` | 0.01 | допустимое падение precision |
| `min_accept_f1` / `min_accept_precision` | 0.80 / 0.75 | порог первой активации |

Версии лежат в `autopilot/data/models/`, активная — в `active.json`.
Откат: `py -3 -m autopilot models --promote <version>`.
`trainer.promote_to_app = true` дополнительно копирует активную модель
в `ml/doreposta/fake_model.joblib` для backend и фронтенда
(по умолчанию **выключено** — не меняем артефакты приложения).

## Очередь и пороги разметки

Материал без убедительного основания не размечается: он возвращается
в очередь и перепроверяется следующим циклом.

| Параметр | Значение | Смысл |
|---|---|---|
| `min_label_confidence` | 0.60 | ниже — метка не идёт в обучение |
| `claims_full_support_conf` | 0.80 | все утверждения подтверждены |
| `claims_full_contradict_conf` | 0.85 | все утверждения опровергнуты |
| `claims_partial_conf` | 0.70 | часть утверждений подтверждена/опровергнута |
| `min_sources_for_real` | 2 | независимых домена для метки `real` |
| `max_verify_attempts` | 3 | попыток проверки одного материала |
| `uncertain_ttl_hours` | 48 | после — `archived_uncertain` |

`archived_uncertain` — не потеря данных: материал остаётся в базе
для отчётности и экспорта, но больше не тратит CPU и сеть. Архивные
записи не попадают в обучение.

**Бюджет модели.** Два лимита, действуют одновременно:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `llm_hourly_budget` | 40 | вызовов в час |
| `llm_daily_budget` | 600 | вызовов в сутки (`0` — без лимита) |
| `min_calls_per_item` | 3 | сколько нужно на один материал |

Считаются все шаги: извлечение утверждений, оценка, арбитр. Когда любой
из лимитов исчерпан, проверка останавливается и материалы остаются
в очереди — попытки не тратятся впустую. Один материал стоит 2–4 вызова,
значит 600 вызовов в сутки — это примерно 150–250 проверок.

Оценка стоимости: при `gpt-4o-mini` (~$0.15 / $0.60 за 1M токенов) одна
проверка — около 3–4 тысяч токенов, то есть меньше $0.01. 600 вызовов
в сутки ≈ $0.10–0.30 в сутки. Точную цифру смотрите в биллинге провайдера.
Поставьте `llm_daily_budget` по карману: это жёсткий потолок, выше него
система не пойдёт даже при пустой очереди.

## Где что лежит

```
autopilot/
  config.json            источники и настройки
  requirements.txt       зависимости
  RUN_AUTOPILOT.ps1      запуск 24/7
  STOP_AUTOPILOT.ps1     остановка
  data/
    autopilot.db         SQLite: items, fetch_log, llm_calls, arbitrations,
                         training_runs, model_versions
    models/              версии модели, holdout.jsonl, active.json
    logs/autopilot.log   лог с ротацией (5 МБ × 5)
```

## Тесты

```powershell
py -3 -m pytest autopilot/tests -q     # без сети и без вызовов модели
```

Тесты покрывают нормализацию текста и хеши, SimHash, разбор RSS/Telegram,
`robots.txt`, проверку дословности цитат, фильтрацию выдуманных цитат,
дедупликацию и метки в SQLite, горячую перезагрузку модели и отказ от
деградирующей версии при обучении.
